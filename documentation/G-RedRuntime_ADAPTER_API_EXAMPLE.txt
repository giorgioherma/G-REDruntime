G-RedRuntime 0.6 integration adapter API sketch
===============================================
This file is documentation only; it is NOT compiled.

Adapters are integration-overlay files. Keep them with the existing mod they adapt;
do not move optional-mod adapters into the G-RedRuntime core because naming optional
mod types there would turn those mods into hard compile dependencies.

Prefer an additive adapter/wrapper when it can preserve behavior. Patch an original
mod file only when the measured optimization cannot be expressed safely from an
additive boundary. Existing mod paths and public APIs remain authoritative.

All framework types live in:

  module GRedRuntime

Typical adapter setup:

  let runtime = GRedRuntime.Runtime.Get(gameInstance);
  let player = runtime.GetStateCache().GetPlayer();
  let quests = runtime.GetStateCache().GetQuestsSystem();

DIRTY FLAGS
-----------
  runtime.GetDirtyFlags().Mark(n"MY_STATE");
  if runtime.GetDirtyFlags().Consume(n"MY_STATE") { ... }

EVENT BUS
---------
Subclass GRedRuntime.EventListener and implement OnGRedEvent.
Register with:

  let handle = runtime.GetEventBus().Subscribe(n"PLAYER", listener);

INPUT HUB
---------
Subclass GRedRuntime.InputListener and implement OnGRedInput.
Register one action:

  let handle = runtime.GetInputHub().Subscribe(n"Jump", listener);

Use n"" or n"*" to receive every action. Prefer a specific action whenever the
integration does not truly need wildcard traffic.

SCHEDULER
---------
Subclass GRedRuntime.ScheduledJob and implement Execute(runtime).
Configure and register:

  job.Configure(n"MyJob", 0.25, true);
  let handle = runtime.GetScheduler().Register(job);

The central scheduler does not run until the first job is registered.

HOOK BUS
--------
Subclass GRedRuntime.HookListener and implement OnGRedHook.
Framework-owned wrappers may publish typed HookContext subclasses to this bus.
Do not add an optional mod's wrapper to the core merely to centralize it; keep
optional-mod adapters in that mod's integration overlay.
